## Best architecture for the first version

For FLASH-UI prototypes:

```text
Static HTML + Tailwind + vanilla JS
↓
localStorage for personal dashboard data
↓
Static JSON for resource cards / templates / product data
↓
Tally or Google Forms for submissions
↓
Google Sheets or Notion as lightweight backend
↓
Vercel static hosting
```

Then only upgrade when pain demands it:

```text
Clerk = partner login
Supabase = partner records, leads, tasks, pipeline
Firebase = quick auth + Firestore dashboard data
Wix Members = easiest bridge into Moonshine frontend
Vercel API routes = secure webhooks/API keys
```

Do **not** start with a full SaaS backend unless the dashboard proves partners will actually use it. Start with static tools that slap, ship fast, and create behavior. Then put the database behind the winners.
